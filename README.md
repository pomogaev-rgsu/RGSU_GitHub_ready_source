# РГСУ: учебный прототип системы выдачи справок

Реализованный и локально проверенный учебный MVP: личные кабинеты обучающегося, сотрудника и администратора; регистрация заявок; история изменения статусов; уведомления; контроль доступа; генерация демонстрационных PDF по трём типам документов.

**Важное ограничение:** это независимый учебный прототип без подключения к информационным системам РГСУ, подписания документов, официального согласования или использования настоящих персональных данных. PDF имеет маркировку «Демонстрационный образец» и не является официальной справкой.

## Технологии

Python 3, FastAPI, SQLAlchemy, Jinja2, SQLite (локальный демонстрационный режим), ReportLab, HTML/CSS, JavaScript.

⚠️ В исходном тексте ВКР заявлены Django 5.2 и PostgreSQL. Этот прототип реализован на **другом стеке**. Для согласования с ВКР необходимо либо портировать код на Django/PostgreSQL, либо корректно исправить описание технологий в работе. Не представлять этот проект как реализованный на Django.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
export APP_SECRET_KEY='generate-a-unique-long-random-secret'   # Windows PowerShell: $env:APP_SECRET_KEY='...' 
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. База `demo.db` создаётся при первом запуске и заполняется исключительно вымышленными тестовыми данными. Файл базы данных не включен в репозиторий. Если `APP_SECRET_KEY` не задан, при каждом запуске создаётся случайный ключ сеанса, и предыдущие сеансы перестают действовать.

## Статусы

Подана → На проверке → В оформлении → На подписании → Готова к выдаче → Выдана. Возможны возвраты на уточнение и отклонение. Изменение допускается исключительно по предусмотренным переходам и с проверкой роли. История сохраняет все переходы.

## Функциональные ограничения

- Используется демонстрационная SQLite, отсутствует интеграция с базами РГСУ и официальными приказами.
- Авторизация, сессии и CSRF включены, но решение **не проходило** промышленный аудит безопасности или защиту персональных данных по уровню ИСПДн.
- Реального сервиса уведомлений email/SMS нет: сообщения доступны внутри личного кабинета.
- Документы создаются как учебные образцы, не заверяются ЭП. Отметка «Готова к выдаче» в приложении — учебный статус.
- Не реализованы доступность 99%, восстановление за 4 часа, официальные печатные шаблоны, нагрузочное тестирование 30 пользователей.
- Пароли демо-аккаунтов общедоступны. Перед использованием вне локальной среды удалите тестовые аккаунты, смените секрет и настройте HTTPS, резервное копирование, аудит.

## Тестирование

Для тестов установите `pip install -r requirements-dev.txt`, затем запустите `python -m pytest tests -q`. Скриншоты получены из реально возвращаемых приложением HTML-страниц и отрисованы Chromium. В рабочей среде браузер блокировал переходы к localhost, поэтому HTML для снимков загружался через HTTP-клиент, а CSS и JavaScript внедрялись локально (см. `capture_screenshots.py`). Картинки не являются нарисованными макетами. Скриншоты — в каталоге `screenshots`. PDF-примеры — `outputs/sample_certificate.pdf`, `outputs/sample_period.pdf`, `outputs/sample_order.pdf`.

## Перенос и шрифты

Для формирования русскоязычного PDF нужен установленный в операционной системе TrueType-шрифт с кириллицей. В Linux по умолчанию используется системный DejaVu Sans, в Windows — Arial. При необходимости задайте переменные `RGSU_FONT_REGULAR` и `RGSU_FONT_BOLD` с путями к своим легально установленным шрифтам. Файлы шрифтов в архив не включены.

Параметр `DATABASE_URL` допускает подключение иной СУБД при установке соответствующего драйвера. Работа с PostgreSQL в данном запуске не проверялась; сценарии тестировались на SQLite.
